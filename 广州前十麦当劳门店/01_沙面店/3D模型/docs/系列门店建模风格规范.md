# 广州麦当劳门店系列｜3D 建模创作流程与风格规范

**版本**：v1.1  
**基准项目**：01_沙面店（v1.0）→ 02_北京路丽都酒店店（v1.1 增加门店灯光章节）  
**适用范围**：后续其他门店的单体建筑 / 临街立面模型。规范只定义统一方法，不预设其他门店造型。

## 1. 核心原则

1. **照片优先**：门店实拍是唯一视觉依据；通用品牌效果图只能辅助理解材质，不能决定建筑结构。
2. **一店一依据**：不得把其他门店的拱、招牌、楼层、颜色或店型套用到当前门店。
3. **可见与推定分离**：所有不可见结构必须标为推定或简化，不伪装成照片事实。
4. **建筑本体优先**：不添加人物、车辆、道路、绿化、图标、购物车、全息构件或无关场景。
5. **识别特征优先**：先保证轮廓、层数、开间、门窗、屋顶、招牌和主色，再补充线脚与室内暗示。
6. **可编辑交付**：语义分组、参数配置、可复建脚本和通用交换格式缺一不可。
7. **非测绘声明**：没有实测数据时，所有尺寸只能称“照片推定”，不得用于施工。

## 2. 标准工作流程

### 阶段 A｜照片核验

- 确认照片确属目标门店，优先使用带门头、建筑名、地址环境或平台水印的图。
- 以宽景确定面宽和层数，以正立面确定开间，以近景确定线脚、门框和招牌。
- 为每张图指定用途：`MASSING` 体量 / `FACADE` 立面 / `DETAIL` 细节 / `INTERIOR` 室内 / `ROOF` 屋顶。
- 异地同名店、通用品牌素材和无法核验的图搜结果不得进入视觉依据集。

**输出**：参考联系表、照片分工表、可用 / 不可用照片说明。

### 阶段 B｜照片分析

按固定顺序记录：

1. 建筑类型：独立店、商场内店、历史建筑首层、交通枢纽店等。
2. 轮廓：面宽、进深是否可见、层数、屋顶形式、附属体块。
3. 立面网格：开间数量、门窗中心、柱间墙、拱或雨篷。
4. 招牌：类型、位置、尺寸比例、厚度、是否发光。
5. 材质：主墙、玻璃、金属、屋面、室内色温。
6. 不可见项：背面、侧面、屋顶、真实进深、被遮挡开间。

**输出**：门店照片分析与建模记录。

### 阶段 C｜比例与细节取舍

- 有公开图纸或实测值时优先使用，并写明来源。
- 无实测时以门高、标准砖、台阶或层高作为视觉标尺；人物只可作粗略参考，不能作为精确尺。
- 模型采用米制，Z 向上；主立面朝本地 `-Y`，建筑向 `+Y` 延伸。
- 首层地面标高原则上为 `0`；入口台阶按片单独建模。
- 允许为视觉协调微调推定尺寸，但不得改变照片可辨的开间和构件关系。

细节优先级：

| 优先级 | 内容 | 标准 |
| --- | --- | --- |
| P0 | 轮廓、层数、面宽、门窗、招牌、主色 | 必须完成 |
| P1 | 拱圈、窗框、雨篷、台阶、线脚 | 照片可见则完成 |
| P2 | 石材分缝、门把手、窗台托块、少量灯管 | 适度完成 |
| P3 | 室内家具、商品、污渍、海报、微小五金 | 默认省略，除非项目专门要求 |

### 阶段 D｜建模与分组

统一集合：

| 集合 | 内容 | 是否导出 |
| --- | --- | --- |
| `01_HOST_SHELL` | 侧墙、后墙、楼板、屋顶 | 是 |
| `02_FACADE_STONE` | 主立面、分缝、线脚 | 是 |
| `03_ARCHITECTURAL_ARCHES` | 拱、柱、特殊立面构件 | 是 |
| `04_GLAZING_AND_DOORS` | 玻璃、窗框、门、室内背板 | 是 |
| `05_SIGNAGE` | 品牌字、窗篷、独立招牌 | 是 |
| `06_ENTRANCE_STEPS` | 门槛、台阶、坡道 | 是 |
| `90_PREVIEW_STUDIO_EXCLUDED_FROM_EXPORT` | 相机、灯光、预览地面 | 否 |
| `99_REFERENCE_METADATA` | 参考说明与元数据 | 否 |

对象命名采用 `部位_构件_序号`，例如 `Arch_rounded_moulding_01`、`Entrance_step_03`。避免全部保留为“立方体.001”。

### 阶段 E｜材质、光照与预览

- 材质名称使用 `类别_用途`，例如 `STONE_pale_grey_limestone`。
- 玻璃保留深色与反射，不做全透明“空窗”；室内只用低细节暖色背板。
- 品牌黄作为小面积视觉焦点，不大面积染到建筑或灯光上。
- 三点柔光：暖主光、冷补光、顶部轮廓光；中性世界背景。
- 使用 AgX 色彩管理；禁止强泛光、霓虹描边、全息网格和过度景深。
- 三个固定预览：正立面、三分之四、首层细节。复杂屋顶可补屋顶视角。
- 若门店照片含明确灯光特征（夜景实拍、发光招牌、灯箱），执行下方「门店灯光（v1.1）」章节。

### 门店灯光（v1.1，自 02_丽都酒店店起）

照片中有明确灯光证据的门店，灯光是一等交付物，规则如下：

1. **只建照片里有的灯**：每一处灯光元素（发光招牌、筒灯、灯箱、室内透出的暖光）都必须能指到具体照片；不得套用通用夜景模板，不得添加照片中没有的灯带、地灯、投影。
2. **双状态**：`.blend` 中保留日景（90 预览灯光）与夜景（07 门店灯光）两组状态；夜景只亮门店自己的灯，世界背景调暗。
3. **集合**：门店灯放 `07_LIGHTING_STORE`，随模型导出（GLB 使用 KHR punctual lights）；预览影棚灯仍在 `90`，不导出。
   - **禁止用面光（AREA）做门店灯**：KHR_lights_punctual 只有 spot/point/directional，面光在 GLB 里会被静默丢弃。需要柔和洗光时用 130°–150° 超宽聚光灯（spot_blend 0.8+）模拟。预览影棚灯不受此限（本来就不导出）。
4. **自发光优先**：招牌与灯箱以自发光材质表达（任何查看器可见），真实灯光对象负责洗墙、落地光斑与玻璃透光；两者必须成对存在。
5. **色温从照片读**：菜单灯箱的冷青、室内的暖橙、招牌的品牌黄，均按片取色，记录在设计文档的灯光表中。
6. **克制**：禁止光晕后期、泛光阈值拉满等“夜景美化”；灯光强弱以接近照片观感为准。
7. **预览**：灯光门店至少出 5 张预览——日景正视 / 日景三分之四 / 夜景正视 / 夜景三分之四 / 夜景入口细节；有门拉手、独立灯箱等特写构件时加第 6 张夜景构件特写。
8. **特写构件可信原则**（甜品站、门拉手等，自 02_丽都酒店店起）：独立落地构件必须有底座/地脚等承重关系；门窗拉手必须有安装位置（离地约 1.05m）、固定件（支撑杆 + 底座压板）和端部收口，材质用拉丝不锈钢（metal ≈ 0.9, rough ≈ 0.26–0.4）。

### 阶段 F｜验证与交付

必须检查：

- GLB 可解析，节点、网格、材质数量正常。
- OBJ 有对应 MTL，FBX 可重新导入。
- BLEND 打开后集合、文字、相机和材质存在。
- 导出文件不含 `90` 预览集合，不含人物、车辆和周边场景。
- 预览中没有明显穿插、反向法线、悬浮招牌、台阶方向错误或文字缺失。
- 文档中的尺寸、张数、文件清单与实际产物一致。

## 3. 比例与精度分级

| 等级 | 依据 | 可用途 | 标注方式 |
| --- | --- | --- | --- |
| L1 视觉复原 | 单店实拍，尺寸推定 | 展示、档案、美术 | “照片推定，非实测” |
| L2 多视角校准 | 正侧后、多张照片 + 部分公开尺寸 | 较精细展示 | “多视角校准，局部推定” |
| L3 测绘级 | 图纸 / 点云 / 实测 | 工程辅助 | 写明来源、误差与日期 |

当前沙面店为 **L1**。系列默认不得把 L1 模型描述为“精确复刻”。

## 4. 材质与配色规范

### 4.1 取色方法

1. 从非过曝、非强滤镜区域目测主色。
2. 同一材质取一个系列标准色，避免每张色差导致模型花碎。
3. 主墙与线脚保持低对比；玻璃和窗篷承担主要深色对比。
4. 发光字只允许低强度自发光，不用光晕掩盖字形。

### 4.2 沙面基准色板

| 用途 | 色值 |
| --- | --- |
| 主石墙 | `#C8C9C4` |
| 石材线脚 | `#E0E0D8` |
| 石材分缝 | `#A9AAA5` |
| 黑色窗篷 | `#171918` |
| 深色玻璃 | `#34403B` |
| 深灰金属 | `#353B39` |
| 金拱门黄 | `#FFC72C` |
| 暖白立体字 | `#F3F2E9` |
| 暖色室内 | `#8F5B34` |

后续门店可以换主墙色，但必须沿用“主色 / 辅色 / 深色 / 品牌色 / 室内色”的材质槽位。

## 5. 文件组织与命名

每家门店独立放在自己的目录中：

```text
NN_门店名/
└── 3D模型/
    ├── README.md
    ├── viewer.html
    ├── models/
    │   ├── StoreKey_McDonalds.blend
    │   ├── StoreKey_McDonalds.glb
    │   ├── StoreKey_McDonalds.obj
    │   ├── StoreKey_McDonalds.mtl
    │   ├── StoreKey_McDonalds.fbx
    │   └── model_manifest.json
    ├── previews/
    │   ├── StoreKey_01_front.png
    │   ├── StoreKey_02_oblique.png
    │   ├── StoreKey_03_detail.png
    │   └── StoreKey_preview_board.jpg
    ├── references/
    │   └── 门店名_建模视觉依据联系表.jpg
    ├── src/
    │   ├── storekey_config.json
    │   └── build_storekey.py
    └── docs/
        ├── 门店名_照片分析与建模记录.md
        └── 系列门店建模风格规范.md
```

- 文件与代码标识使用 ASCII `PascalCase / snake_case`，避免跨软件路径问题。
- 中文仅用于文档、门店显示名和必要的招牌文字。
- 版本文件采用 `_v01`、`_v02`；正式交付不保留无意义的 `final_final`。
- 模型文件统一使用门店键，例如 `Shamian_McDonalds.glb`。

## 6. 复用方法

1. 复制沙面店的目录骨架和通用规范。
2. 替换目标门店照片，重新完成阶段 A–C；不得只替换招牌文字。
3. 在 JSON 中修改面宽、进深、层高、开间、拱参数、门窗位置和色板。
4. 在脚本中保留通用函数，按目标门店增删构件；其他店没有拱时不得为了系列统一强行保留拱。
5. 按同一集合、材质槽位、灯光、相机和导出规则生成。
6. 用固定检查表验收，并记录与沙面店不同的合理细节。

**系列一致的是方法与呈现，不是所有门店的造型。**

## 7. 最低交付验收清单

- [ ] 只包含目标门店，无其他门店拼接。
- [ ] 轮廓、层数、门窗和招牌可由照片追溯。
- [ ] 不可见区域有简化说明。
- [ ] BLEND / GLB / OBJ+MTL / FBX 均存在且可读取。
- [ ] 至少三张预览和一张预览汇总板。
- [ ] 交互查看器可旋转、缩放并切换固定视角。
- [ ] 配置、脚本、模型清单和照片分析齐全。
- [ ] 无人物、车辆、周边场景、购物车、互联网符号或全息装饰。
- [ ] 明示照片推定尺寸、非施工用途和参考图版权边界。
